# NFS - TU111,2049

### Default Configuration

* `/etc/exports`&#x20;
* <table data-header-hidden><thead><tr><th width="167.28570556640625">Option</th><th>Description</th></tr></thead><tbody><tr><td><code>rw</code></td><td>Read and write permissions.</td></tr><tr><td><code>ro</code></td><td>Read only permissions.</td></tr><tr><td><code>sync</code></td><td>Synchronous data transfer. (A bit slower)</td></tr><tr><td><code>async</code></td><td>Asynchronous data transfer. (A bit faster)</td></tr><tr><td><code>secure</code></td><td>Ports above 1024 will not be used.</td></tr><tr><td><code>insecure</code></td><td>Ports above 1024 will be used.</td></tr><tr><td><code>no_subtree_check</code></td><td>This option disables the checking of subdirectory trees.</td></tr><tr><td><code>root_squash</code></td><td>Assigns all permissions to files of root UID/GID 0 to the UID/GID of anonymous, which prevents <code>root</code> from accessing files on an NFS mount.</td></tr></tbody></table>

### Dangerous Settings

* <table data-header-hidden><thead><tr><th width="159.28570556640625">Option</th><th>Description</th></tr></thead><tbody><tr><td><code>rw</code></td><td>Read and write permissions.</td></tr><tr><td><code>insecure</code></td><td>Ports above 1024 will be used.</td></tr><tr><td><code>nohide</code></td><td>If another file system was mounted below an exported directory, this directory is exported by its own exports entry.</td></tr><tr><td><code>no_root_squash</code></td><td>All files created by root are kept with the UID/GID 0.</td></tr></tbody></table>

### Footprinting

{% endcode %}

### List NFS Mount

```shellscript
showmount -e <ip>
```

### Mount the Share

{% code lineNumbers="true" fullWidth="false" %}
```shellscript
sudo mount -t nfs <IP>:/ /<mount path> -o nolock,ro
sudo mount -t nfs -o ro <ip>:/<sharename> /<mount path> 
sudo mount -t nfs -o ro,vers=2 <ip>:/<sharename> /<mount path> 
sudo mount -t nfs -o rw <ip>:/sharename <mount-path>
sudo mount -t nfs -o rw,vers=2 <ip>:/<sharename> /<mount path> 
```
{% endcode %}

### Enumeration

* **List Contents with Usernames & Group Names**
  * `ls -l <sharename>`&#x20;
* **List Contents with UIDs & GUIDs**
  * `ls -n <sharename>`&#x20;

{% hint style="info" %}
If we have access to the system via SSH and want to read files from another folder that a specific user can read, we would need to upload a shell to the NFS share that has the `SUID` of that user and then run the shell via the SSH user.
{% endhint %}

### Unmount Share

```shellscript
sudo umount <mount path>
```
